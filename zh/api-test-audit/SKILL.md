# 接口测试偏差检查

对照画像、行为清单和代码，找出接口测试的缺口和问题，输出分级报告。术语（画像、替身用例、真实用例、样本、行为清单、现状快照）与 [api-test-gen](../api-test-gen/SKILL.md) 相同。

## 硬性规则

1. 只报告，不修改测试代码、业务代码、样本和画像；修复交给 `/api-test-gen` 或用户。
2. 报告中不贴个人信息原文：命中的手机号、身份证号等只写文件、字段路径和类别。
3. 每条问题都写明证据（文件路径和行号，或命令输出摘要），没有证据的不报。

## 范围

| 用户说法 | 范围 |
|---|---|
| 未指定 | 当前改动：`git diff --name-only <baseBranch>...HEAD` 加 `git status --porcelain`，映射到接口的方法同 [api-test-gen](../api-test-gen/SKILL.md) 第 2 步 |
| 指定模块、Controller、路径 | 只检查指定部分 |
| 全量 | 画像中所有模块；跳过画像 `exclude` 中的路径 |

没有画像时，B、D 类中依赖画像的检查项跳过，并在报告中说明；其余照常检查。

## 工作流

```
- [ ] 1. 读画像和行为清单
- [ ] 2. 列出接口和测试
- [ ] 3. 编译测试代码
- [ ] 4. 逐项检查
- [ ] 5. 报告
```

### 1. 读画像和行为清单

读取 `.api-test/profile.yaml` 和 `.api-test/behaviors/**`。样本规范见 [fixture-spec.md](../api-test-shared/fixture-spec.md)，写法规范见 [java21-boot3.md](../api-test-shared/java21-boot3.md) 和 [java8-boot2.md](../api-test-shared/java8-boot2.md)。

### 2. 列出接口和测试

1. 扫描范围内的 Controller：类上与方法上的 `@RequestMapping`、`@GetMapping`、`@PostMapping`、`@PutMapping`、`@DeleteMapping`、`@PatchMapping` 拼出完整路径。
2. 在测试目录中搜索每个路径和 Controller 类名，得到“接口 → 测试类和方法”的对应表。
3. 按类名后缀区分：`*ApiTest`、`*FlowTest` 为替身用例，`*IT` 为真实用例，其他为已有测试。

### 3. 编译测试代码

按 [api-test-run](../api-test-run/SKILL.md) 的 JDK 选择和引号规则运行画像 `commands.testCompile`，不运行测试。被替换的方法改名或改签名后，测试会在这里编译失败。编译失败作为 D1 报告，其余检查照常进行。

### 4. 逐项检查

**A 覆盖**

| 编号 | 检查 | 级别 |
|---|---|---|
| A1 | 范围内的接口没有任何测试；当前改动范围下，改动过的接口没有新增或更新的测试 | 中 |
| A2 | 接口只有替身用例没有真实用例，或只有真实用例没有替身用例 | 低 |
| A3 | 行为清单中已确认的用例找不到对应测试方法（按方法上的 `// #编号` 注释和方法名对照） | 中 |
| A4 | 带校验注解的请求 DTO 字段没有对应的拒绝用例 | 低 |

**B 样本**

| 编号 | 检查 | 级别 |
|---|---|---|
| B1 | 落盘样本在 `fixtures/<接口名>.sources.yaml` 中没有对应 `path`，或该条的 `source`、`type` 为空 | 中 |
| B2 | `type` 指向的类已不存在；或样本中的字段在该类中不存在、该类新增的字段样本中没有 | 中 |
| B3 | `source: synthetic` 但依赖是只读调用，可以录制 | 低 |
| B4 | `capturedAt` 距今超过 180 天 | 低 |
| B5 | 样本文件没有被任何测试引用 | 低 |

B2 的类在依赖 jar 中、读不到源码时，跳过字段对比，只检查类是否存在。

**C 安全**

| 编号 | 检查 | 级别 |
|---|---|---|
| C1 | `src/test/resources/fixtures/` 中命中个人信息正则（手机号、身份证号、邮箱），或按画像 `redact` 规则命中的字段值不是规定的替换值 | 高 |
| C2 | `target/api-test-samples/` 下的文件被 git 跟踪，或该目录没有被 `.gitignore` 忽略 | 高 |
| C3 | 真实用例的调用链经过画像 `dailyRun.forbiddenCalls` 中的方法，却没有对应的禁止调用守卫 | 高 |
| C4 | 真实用例调用链中有写操作或计费调用，且行为清单中没有单独确认的记录 | 高 |
| C5 | 测试代码中硬编码了环境地址、账号、密码、密钥或 token | 高 |

用 `git ls-files` 和 `git check-ignore` 检查 C2。

**D 写法**

| 编号 | 检查 | 级别 |
|---|---|---|
| D1 | 测试代码编译失败 | 高 |
| D2 | 写法与模块版本不符：Java 8 模块使用禁用的语法或 API；`javax` 与 `jakarta` 混用；JUnit 版本与画像不符 | 中 |
| D3 | 替身注解与 Spring Boot 版本不符：3.4 及以上仍用 `@MockBean` / `@SpyBean`，或 3.4 以下用了 `@MockitoBean` | 低 |
| D4 | 替身用例实际连了真实依赖：`*FlowTest` 的调用链经过画像 `boundaries` 中的类型却没有替换 | 中 |
| D5 | 测试代码中写死启动参数（`@SpringBootTest(properties = ...)`、`@TestPropertySource` 中的 Apollo、Eureka 等开关） | 低 |
| D6 | 类名、位置不符合写法文件中的命名规则 | 低 |
| D7 | 画像 `boot` 中为 `daily` 的层，测试类缺少 daily 启动条件，默认 `mvn test` 会因连不上配置或端口冲突而失败 | 高 |

**E 有效性**

| 编号 | 检查 | 级别 |
|---|---|---|
| E1 | 测试方法没有断言：没有 `andExpect`、`assertThat`、`assertEquals`、`verify` 等 | 中 |
| E2 | 行为清单中期望来源为现状快照的用例，没有用户确认记录 | 中 |
| E3 | 测试被 `@Disabled` / `@Ignore` 跳过，且没有写明原因 | 低 |

级别含义：

- **高**：会泄露数据、误调用 daily 写接口或计费接口，或测试无法运行。
- **中**：测试结果可能误导人，或存在覆盖缺口。
- **低**：规范和维护性问题。
